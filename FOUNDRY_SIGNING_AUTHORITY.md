# Foundry Signing Authority

**Status:** RSA-PSS signing operational; private key outside git; E.V.E. verifies with the public key only.

Implementation: `lib/foundry/evidence-manifest.ts`.

## Signer

- **Algorithm:** RSASSA-PSS-SHA256 (`RsaPssEvidenceManifestSigner`) — `RSA_PKCS1_PSS_PADDING`, saltLength 32, SHA-256. Signature format: `rsa-pss-sha256:<base64>`.
- **Provider select:** `FOUNDRY_EVIDENCE_SIGNER_PROVIDER=local-kms-rsa` with `FOUNDRY_EVIDENCE_KMS_PRIVATE_KEY_PEM`. (HMAC and external-KMS remain supported; the complete factory proof uses RSA-PSS.)
- **Signer identity:** `FOUNDRY_EVIDENCE_SIGNING_KEY_ID` / `_KEY_VERSION` — this proof: `foundry-eve-proof-rsa` / `v1`. `signerProvider=local-kms-rsa`.

## Canonicalization / coverage

- `canonicalJson` = recursively key-sorted JSON, `undefined` filtered.
- `manifestHash = sha256Canonical(unsignedManifest)` over `{manifestVersion, executionId, tenantId, capabilityId, producerIdentity, executionTimestamp, evidenceItems, issuedAt}`.
- Signature is over `canonicalJson({manifestHash})`. Mutating any covered field changes `manifestHash` → signature no longer verifies (tamper-evident). Each `evidenceItems[].hash` is `sha256Canonical` of its content.

## Local key handling (this mission)

- A dedicated local-development RSA-2048 keypair is generated by `scripts/start-foundry-local.ps1` under `.secrets/` (added to `.gitignore`: `.secrets/`, `*.pem`, `*.key`).
- Private key: `.secrets/foundry-evidence-private.pem` (mode-restricted). **Never committed, never printed, never copied into VERIDIAN/E.V.E.**
- Public key: `.secrets/foundry-evidence-public.pem` — this is what E.V.E. loads into its trusted registry.
- Fingerprint (sha256, first 32 hex) is logged; secret contents never are.

## Public-key registration (E.V.E. side)

E.V.E. loads the public key via `FOUNDRY_EVIDENCE_KMS_PUBLIC_KEY_PEM` (+ matching key id/version) or `EVE_EVIDENCE_PUBLIC_KEYS`, keyed `keyId::keyVersion`. E.V.E. never receives the private key.

## Rotation / revocation

- Rotation: issue a new keypair with a new `keyVersion` (or key id); register the new public key in E.V.E. Historical manifests remain verifiable while their signing public key stays registered.
- Revocation: mark a registry entry `revoked:true` in E.V.E. → any manifest from that signer fails closed (BLOCKED).

## Verification failure modes (all fail closed, proven)

CHECKSUM_MISMATCH (tamper), INVALID_SIGNATURE (forged/wrong private key), UNKNOWN_SIGNER (untrusted key id), REVOKED (BLOCKED), EXPIRED, REPLAYED, SCOPE_MISMATCH, unsupported-algorithm (BLOCKED).
